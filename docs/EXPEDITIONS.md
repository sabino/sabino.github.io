# Field expeditions and encounter contracts

This expansion adds three complete commission loops to reachable settlements. It does not change terrain generation, mutate chunks, turn passive fauna into enemies, respawn dead actors, or replace the existing campaign. Another settlement supplies new addressed sites: repeatability comes from exploration, not a daily reset of shared death records.

Names, prose, mechanics and UI are original Verso work. These modules add no external art, sound or other assets. Sound cues use the existing, licensed Foley library through the integrator’s combat event hooks. Civilization era, resident names and roles, town names, biome and ecology come from the existing world. The botanical contract protects existing wildlife habitat; it does not create hostile birds or grazers.

## Integration contract

`ExpeditionCatalog(world)` owns a 12-town bounded cache. `plansForTown(town)` and `plansAround(x, y, radius)` return plans with site, giver, costs, rewards and a small set of standard `Npc` records. `enemiesAround` returns fresh copies within a maximum 32-tile radius. `enemyById` validates a canonical address and reconstructs the settlement from its coordinates; there is no world-wide search or client-supplied spawn payload.

Actor addresses are `expedition:<uint32 seed>:<town x>:<town y>:<road|relay|garden>:<archetype>:<index>`. Geography uses the established generation version and a separate `expedition-v1` seed namespace. Original town residents retain their original IDs, appearances and locations. Maximum eight actors per town: three road, two relay, three garden. Each site has a separate angular sector and starts at least `max(36, town.radius + 16)` tiles from the town center, protecting the established household resource band. Placement avoids building/site/settlement/cultivated/road cells and requires open adjacent standing cells. A bounded A\* checks reachability with operable doors without actually opening doors or carving terrain. If unusual geography has no valid reachable site, the catalog omits that site rather than spawning into water or walls.

`encounterPattern(id, seed, hp, maxHp, time)` supplies one deterministic pattern. Its `shape`, locked heading, windup, range, recovery, angles and damage must be captured when an intent begins. Do not reselect a pattern during an in-flight intent: a hit crossing the warden’s half-health threshold changes the _next_ attack, not an already advertised shape. `encounterContains` tests world-space hit geometry; the authority must additionally retain line-of-sight/wall collision. `encounterSteering` requests a normalized chase/kite/hold vector; existing collision owns the actual movement. Standard non-expedition hostiles retain their existing behavior.

The root session saves `ExpeditionState` as an optional additive field. Missing/invalid old state restores to an empty ledger. `observeExpeditions` runs at a bounded discovery cadence and records survey/time observations. `expeditionStatus` derives progress from persistent defeated IDs. In multiplayer those IDs must come from the existing authority death/removal receipts, never a claimed local attack. `claimExpedition` atomically checks location, level, supplies and full clearance, deducts personal supplies, and marks one permanent receipt before returning reward data. The caller then grants coins, XP, profession practice and the generated implement through established inventory APIs, and can record aid in the giver’s existing NPC memory. The current architecture treats personal inventories/progression as local state; this does not claim a new cheat-proof server economy.

The ledger retains at most 256 receipts. It refuses new discoveries at capacity and never evicts old receipts (eviction would enable repeated rewards). A completed commission remains complete across reloads. Costs are existing inventory IDs, so recipe/tool/gathering flows and old save schemas remain usable. A reward’s implement is an actual `generateArtifact` result selected from a bounded 64-design addressed sequence for contact/projectile/pulse delivery. If none matches, a seeded selection from eight verified reserve blueprints of that delivery guarantees a working weapon. This rare fallback can reuse a reserve blueprint; it does not claim unlimited uniqueness. Existing blueprint generation remains unchanged. Technique families follow the equipped implement's delivery, including a contact implement held by a formerly unarmed resident.

Three earned, mutually exclusive attunements combine with the shared technique foundation:

- **Wayfarer’s rhythm:** a deliberate step readies one technique for three seconds with four less stamina cost; the credit is consumed once.
- **Surveyor’s measure:** techniques deal 15% more damage to an already staggered target. The test must happen before this attack applies its own stagger.
- **Fieldkeeper’s bond:** one successful technique restores four warmth and four breath, once per cast even when it hits several targets.

`chooseAttunement` requires the matching claimed commission. `expeditionTechniqueBonus` exposes the bounded numbers; the session/room authority own timing, one-use receipts and damage execution. Existing progression authentication assumptions apply. The UI must not advertise any lesson until those execution hooks are integrated.

## UI contract

Import `expedition-ui.css` with the application styles. Root modal code owns focus trapping, close/back behavior and restoration. `renderExpeditionPanel(plans,state,context,selectedId)` supplies the body; it renders one active card with native buttons, ordered progress, a collapsed briefing and text equivalents of rewards. Root delegates `data-expedition-action=select|track|claim` with `data-expedition`, and `data-attunement`. `expeditionTracker` supplies the current world-space target and concise compass/distance/progress text. Tracking moves from field site to the contact as combat clears.

At a narrow width the three site tabs remain thumb-size, the two actions wrap rather than overflow, and details are opt-in. Shared dialog scrolling and portrait/mobile control placement remain owned by the mobile lane. Selecting a tab should keep focus on that tab; tracking should close the sheet and restore play focus.

## Validation and performance

`node --experimental-strip-types --test tests/stichos-expeditions.test.ts tests/stichos-encounter-patterns.test.ts` exercises the full reducer transaction, duplicate prevention through save/reload, malformed/cross-world IDs and state, four world generations, actual reachability and unchanged baseline geometry, standard NPC wire validation, generated implement delivery, day/night observation, range/line/radial boundaries, phase transition and steering. UI tests check escaped generated text and native progress/control semantics; native portrait interaction and combat execution are integration gates.

A local 24-seed generation sweep (`seed = index * 7309`, generation 4) produced all three opening sites on all 24 worlds. After the protected town band change, cold catalog construction averaged about 98 ms (maximum 171 ms) on the development host; 100 cached enemy queries per world averaged 0.009 ms/query (maximum per-world mean 0.018 ms). These are host module measurements, not a mobile frame claim. Prewarm the opening catalog before unpausing and build another town’s plans on the discovery path, never inside a render loop. Bounds: at most four towns per query, 96 placement candidates per site with an eight-safe-candidate early exit, 12 reachability attempts each capped at 4096 visits, 12 cached towns, 32-tile actor query radius, and four slots per site (currently no recipe uses more than three).
