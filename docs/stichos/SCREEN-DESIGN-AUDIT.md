# Verso: complete screen design audit and implementation handoff

Status: baseline audit; a different agent must implement the fixes. Reviewer changed no production game source.

Date: 2026-09-11. Baseline: frozen production `app-4jvai5g6.js`, source `0a4e2ed`. Workspace-owned Chromium only; normal states reached with native mouse/keyboard input, read-only DOM measurements. Viewports: 1440×960 desktop, 390×844 mobile, 1366×768 compact laptop. Screenshots are local audit artifacts, not shipped assets.

The user clarified that the main game is a unique multiplayer universe. Stíchos/Theo/Sallas are an explicit legacy story, not the default identity, history, architecture, religion, economy, or item vocabulary of every planet.

## Required implementation order

1. Fix the common modal shell, bounded content, persistent close/navigation, and tab scroll behavior. This repairs many screens at once.
2. Replace the mobile desktop-sidebar overlay with a real inventory drawer and restore access to all primary actions.
3. Remove global legacy-story text from generated lives and worlds, using the actual person/world data. Preserve the legacy narrative when explicitly selected.
4. Make each dense Life screen a compact workspace: overview/detail selection or pagination; avoid one enormous stack of cards.
5. Repair typography scoping, touch targets, meaningful control names, map controls, and chat behavior.
6. Re-run the complete matrix and independently review screenshots. No blanket claim that every state passes because a handful of title screens fit horizontally.

## Acceptance checklist for the implementing agent

- At 390×844 and 1366×768, every screen has a visible close/back control; no content escapes a framed panel; no essential action depends on scrolling a different nested region.
- Each tab opens at its beginning with logical focus, and in-place changes keep the edited control visible.
- Inventory opens to inventory on mobile. All actionable item slots have names, not only quantities.
- Touch primary targets are 44px, or have equivalent invisible hitboxes without overlap. Keyboard focus is visible and properly bounded; Esc closes safely, physical notebook still folds.
- All 18 legacy notebook entries and 4 plant leaves use the intended handwriting/plain-type behavior and remain readable. Generated lives do not inherit Theo’s private history.
- Generic planet/person terminology is derived from the current world/life; legacy Stíchos material appears only in the explicit legacy experience.
- A merchant exposes generated weapon/item art, stats and price before purchase; no weapon family is hidden only at the bottom of a long dialogue.
- Construction and household phase states are legible and actionable; blocking reasons appear beside disabled controls.
- Room sharing fits with several roster members, QR remains scannable, and chat mode labels match the actual outgoing channel.
- Re-run screenshots from normal gameplay and clearly labeled visual fixtures. Compare before/after at full size; retain the game’s existing pixel art.

## Completion note and handoff boundary

Audit complete. The normal baseline contains197 nonfailure labeled captures; the visual fixture pass adds 98 distinct labeled states. No browser console exceptions were recorded in the completed runs. Both native CDP drivers dispose their own browser contexts. Workspace `verso-art-qa` remains with the root agent; the isolated review server remains on 4178 for the implementer. No production source was changed by the reviewer.

The audit found 20 concrete issues, including 9 high-priority items; this is a repair handoff, not a design approval. All main screen families and their principal nested views were inspected. Exact source-only or externally owned gaps remain: real Stripe checkout/payment verification/recovery, native iOS/Android installation sheet, connection-loss/identity-in-use error window variants, every late household work-order branch, every owned-invention branch, every possible procedural dialogue/commission, and 8-person roster density. Those require targeted fixture or actual multiplayer checks after fixes; they must not be reported as visually passed.

The first fixture run tried a nonexistent priest NPC role; it was corrected to the actual archivist role. These were audit-harness issues, not reported product defects. The mobile working-production frame is inconclusive (it shows the empty template despite the provisioned working state); the desktop working frame is valid and the other three mobile production states were inspected.
