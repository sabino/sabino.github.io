# Generated constructions: browser and pixel verification

The actual-input Invent route passed **8/8 checks** on production `app-C8vFBFI2.js` / `app-Obx5hySO.css` on 11 September 2026, with zero runtime exceptions. Its isolated workspace browser context was disposed afterward.

The run imported the previously earned `free-life-home.json` through the native file chooser. That save already had crafting experience, coins and an owned home, but lacked timber. The harness selected actual tools, walked a collision-clear route with keyboard input, and completed repeated strokes on two real trees and one mineral resource. It then exported that legitimately earned material state through the visible Save control before crafting. No gameplay position, health, resources, storage or debug state was assigned.

Verified through visible controls:

- Arbitrary design phrases and **Next invention** changed the component image and generated name. The initial unmet requirements disabled creation.
- At the workbench, `icework 58` produced **Samirol**, a five-part contact implement. It consumed exactly 21 coins, two timber and one ore. The body’s anatomy seed stayed unchanged, and the active appearance carried the same design.
- Gear showed the construction. Equipping a normal staff stowed it; Invent equipped it again; its dynamic satchel entry reopened its inspection page.
- Reload and **Continue** retained the exact equipped design and a single physical object.
- `icework 37` produced the vessel **Eiseisith**. Using it restored a naturally depleted body resource and consumed the vessel once.
- At 390×844, Invent had no horizontal overflow. The actual salvage button removed Samirol, cleared its active state and returned one ore.

This browser route verifies creation and inventory use, not generated-weapon combat damage. The separate session suite covers contact/projectile/pulse properties and collisions.
