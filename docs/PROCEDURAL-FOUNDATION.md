# Verso's procedural foundation

Verso should construct worlds, bodies, objects, missions, and their behavior from reusable parts and combination rules. A different seed should change what exists, what it can do, and why it matters. The author's clarification makes this the foundation of the game; changing terrain layout, colors, and names alone does not satisfy it.

The current browser foundation implements a bounded version of that model. It generates connected anatomies, derives capabilities from structure and world conditions, articulates those bodies, assembles functional equipment, and runs assignments in connected generated terrain. It is not an implementation of unrestricted creature generation or a complete simulated multiverse.

The old sources illustrate nonhuman cubic enemies and four-direction humanoid walk cycles, and call for generated characters. They do **not** specify procedural skeletons, attachment algorithms, or gait solvers. The author's newer clarification explicitly requires nonhumanoid body plans and anatomy-dependent locomotion. The implementation follows that clarified direction without pretending a universal algorithm was hidden in the original document.

All 22 slides and all 13 embedded PPTX GIFs were inspected. There are no embedded videos or audio; the notes contain no additional text. All DOCX GIFs are byte-identical to GIFs in the PPTX, but the DOCX omits the construction and long physics examples. Detailed review artifacts remain in ignored `.dream-loop/review-pptx/`.

## How the implemented composition works

```text
root seed + crossing + recorded actions
  → addressed random streams
  → world conditions, connected terrain, body graphs, equipment components
  → derived capabilities, motion parameters, roles, powers
  → compatible assignment selection and playable effects
  → observations, losses, intervention score, next crossing seed
```

### Differences that already affect play

- Changing anatomy changes support limbs, mass, movement strategy, speed, perception, and whether the host can jump. The same genetic wing structure may fail its lift test under different gravity.
- Dense equipment changes handling/inertia; elastic material changes stored energy; conductivity changes core coupling. Delivery is an actual forward impact, surrounding field, or finite-range projectile.
- Heat burns, cold slows, growth restores living tissue and can establish an escort link, and charge interacts with conductor lifeforms. Shared affinity reduces incoming damage.
- Species role currently matters in selected rules: predators defend their space; conductors respond to charge; losing a pollinator carries a larger intervention penalty. These rules are an initial connection between description and consequence, not a food web.
- The first survey requires distinct species and extraction. Later assignment targets refer to generated species or the generated weapon's core. Host replacement generates another anatomy while retaining the run's existing world and recovery location.

Names, palettes, and surface patterns also vary, but those cosmetic variations are separate from the functional differences above.

## Major work still required

1. **Broader body grammars and compatible controllers.** Add radial and asymmetric branching, longer articulated appendages, multiple effectors, joint limits, and meaningful collision bounds. Reject unsupported assemblies or generate a controller that can use them. Swimming, climbing with graspers, and flight need their own environment models.
2. **Persistent contacts and physical interaction.** Store touchdown/lift-off anchors through turning and acceleration; query terrain under individual effectors; enforce support, collision, and reach. Add movable/stackable parts and constraints so generated beams, platforms, chains, and tools acquire the physical uses shown in slide 20.
3. **Causal missions and ecology.** Model resources, dependencies, relationships, and competing actors. Generate goals from that state, validate a solvable sequence using the current host/equipment capabilities, and let interventions change later opportunities. A role label or a penalty counter is not a living ecology.
4. **Compositional object verbs.** Extend attachment and material rules beyond the current frames. A part should be usable as structure, tool, weapon, or resource when its properties permit it; generated objects need affordances understood by both actors and the mission planner.
5. **Progression, story, and music.** Implement the source's distinction between local offensive skills and cross-world movement skills. Build persistent corporate motives, disclosures, and authored narrative constraints around generated events. Give the soundtrack richer structure and causal responses to play while retaining musical coherence.
6. **Validation across combinations.** Continue reproducibility, graph validity, reachability, mission compatibility, and performance checks across many seeds. Test unsupported/extreme bodies deliberately. Existing generation, motion, world, and session tests establish useful invariants; passing those checks does not prove arbitrary assemblies will work.

For the primary research, equations, solver boundaries, and proposed next steps, see [Morphology-aware procedural motion](research/PROCEDURAL-MOTION.md). IK solves a pose constraint; oscillators supply rhythms; graph grammars supply structure. A complete generative game needs these systems connected to physical rules, playable verbs, world state, and validation. No single equation supplies all of them.
